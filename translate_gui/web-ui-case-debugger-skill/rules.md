# 调试行为规则

以下规则贯穿调试全程，决定「怎么执行、何时停下、何时改写」。

## 1. 操作严格执行，预期仅记录

- 每步的「操作」必须照做。
- 「预期」若不正确，只记录下来（记入步骤记录），不影响继续往下执行。

## 2. 操作执行不下去 → 停下询问

某步操作无法执行（找不到目标、元素不存在、无法完成交互）时：

- 停止当前执行，不跳步、不回退去蒙、不猜测替代方案。
- 停下向用户说明卡点，询问处理方式。

## 3. 信息缺失 → 停下询问

操作时需要填写的值或需要选择的选项在用例中未给出时，视为用例不完整：

- 停下向用户确认缺失信息（如密码值、点击位置）。
- 用户给出结论后，记入澄清记录并继续。

## 4. 禁用试错与猜测

- 定位需多次尝试（试错）才能成功的操作，视为不可靠：停下，将操作改写为确定性描述后再继续。
- 禁止依赖先前调试的「学习记忆」补全当前轮的操作依据。

## 5. 每步快照

- 每步执行完 take a snapshot 记录当前页面状态，作为步骤记录的凭证。

## 6. 项目规则并存

- 项目特定的调试规则写入项目 `agent.md`，与 skill 规则并存，执行时两者都要遵守。

## 7. 动态值不作通过依据

- 随时间/数据源变化的值（数据集时间戳、误差指标数值、精度百分比、项目计数）不作为预期通过依据。
- 只校验稳定的 UI 结构：标题出现/消失、按钮可用状态、元素存在与否。
