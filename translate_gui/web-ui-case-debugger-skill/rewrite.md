# 用例改写规范

把录制用例改写成「可运行用例」时，按下述规则逐条修正。核心目标：执行 Agent 拿到用例后，能**直接按步骤描述执行**，无需询问、无需试错、无需学习。

## 0. 格式

- 用例为 **Markdown（.md）**，步骤内 **操作/预期分离**（见 [可运行用例模板](runnable-template.md)）。
- 操作为命令式逐条执行，预期为校验式逐条验证。

## 1. 消除动态值

- 按钮文本中的时间戳（如「Demo 预测 1 个配置 · 2026/9/8 18:33:07」）会随数据集重建变化。
  - 改写：按名称前缀匹配——「点选名称以『Demo 预测』开头的数据集按钮」。
- 指标数值（误差、精度百分比、计数）为运行期结果，不可预知。
  - 改写：只校验「该指标被展示」，「不校验具体值」。

## 2. 消除歧义

- 存在多个同名元素（如多个同名项目卡片）时，必须指明唯一目标。
  - 改写：指定「点击列表中最新的一个（时间戳最大）」或「按名称搜索后点首个」。

## 3. 补全缺失信息

- 用例未给出的必填值（密码、目标时间等），在改写时补全为确定值。
- 无法由录制内容确定的值，在调试中询问用户后写入。

## 4. 可自动化改写

- 不可自动化的交互（canvas 框选拖拽、图表坐标选点）改写为等价可自动化操作。
  - 改写：时间范围用「预测开始/结束输入框直接填值」；图表选点改为「点击图表中部」。
- 点击位置敏感的时间值（点击后某输入框变为特定时间）不绑定具体值，改校验交互结果（详情面板/标注/按钮出现）。

## 5. 明确等待策略

- AI 推理、长任务：写明「点击执行后主动等待，轮询直到结果区出现『XX』按钮（最长300秒，每10秒一次）」。
- 普通跳转：写明「等待 XX 出现（默认30秒）」。

## 6. 操作/预期分离

- 每步拆为「操作」与「预期」两块。
- 操作：命令式，精确到可直接执行，给出元素文本/占位符/角色，不依赖视觉坐标。
- 预期：校验式，完成标准必须可验证（出现/消失/可用状态），不含模糊语义。
- 预期中的动态数值一律改写为「XX 指标被展示」。

## 7. 登录等通用前置处理

- 登录后弹窗（引导/版本更新）不固定时，写成分支处理：「出现『欢迎使用 TPT 工具箱』点『跳过』；出现『版本更新』点『知道了』」。
